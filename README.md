Парадигма: Объектно-ориентированное программирование.
1. Атрибуты (Свойства)
В классе WORKER инкапсулированы следующие данные, необходимые для выполнения бизнес-логики задачи:
__surname_initials (str): Фамилия и инициалы сотрудника. Используется для идентификации.
__position (str): Занимаемая должность. Важна для кадровой структуры.
__salary (float): Размер заработной платы. Критичен для финансового учета.
__year_hired (int): Год поступления на работу. Базовый атрибут для расчета стажа.
Обоснование: Выбор типов данных обусловлен характером информации (текст для имен, числа для финансов и дат). Опыт работы (experience) не хранится как отдельное поле, а вычисляется динамически через метод get_experience(), что исключает рассинхронизацию данных при изменении текущего года.
2. Методы (Функции)
Класс предоставляет следующий интерфейс для взаимодействия с объектами:
Конструктор __init__: Инициализирует состояние объекта. Поддерживает значения по умолчанию, позволяя создавать пустые объекты или объекты с полными данными.
Геттеры и Сеттеры (@property): Обеспечивают контролируемый доступ к приватным полям. Сеттеры включают валидацию данных (например, проверка, что зарплата неотрицательна, а год приема реалистичен).
display(): Метод для форматированного вывода информации о сотруднике в консоль. Реализует принцип единственной ответственности за представление данных.
get_experience(): Бизнес-логика расчета стажа работы на основе текущего системного времени и года приема.
__del__ (Деструктор): Переопределен для демонстрации жизненного цикла объекта, хотя в Python управление памятью автоматическое.
3. Абстракция
Класс WORKER представляет собой абстракцию реального сущности «Сотрудник компании».
Мы отбросили несущественные для данной задачи детали (цвет глаз, хобби, домашний адрес).
Выделены только те характеристики, которые требуются по условию кейса: идентификация (ФИО), роль в компании (должность), экономический показатель (зарплата) и временной параметр (стаж).
Это позволяет работать с объектами высокого уровня, не задумываясь о том, как именно хранятся данные внутри.
4. Инкапсуляция
В реализации строго соблюден принцип сокрытия данных:
Все атрибуты объявлены как приватные (префикс __ в имени переменной, например, __salary). Это предотвращает прямое изменение данных извне (например, нельзя случайно написать worker.salary = -100).
Доступ к данным осуществляется только через публичные методы-аксессоры (геттеры) и мутаторы (сеттеры).
В сеттерах реализована валидация: попытка установить некорректные данные вызовет исключение ValueError. Это гарантирует целостность состояния объекта (State Integrity).
5. Наследование
В текущей версии задачи класс WORKER является самодостаточным и не наследуется от других пользовательских классов.
Потенциал расширения: При усложнении системы целесообразно ввести базовый класс Person (с полями ФИО, дата рождения) и наследовать от него Worker. Это позволило бы повторно использовать код для других сущностей (клиенты, партнеры).
В данном решении наследование от встроенного типа object происходит неявно (стандарт Python 3).
6. Полиморфизм
В рамках текущего задания полиморфизм не использован явно, так как нет иерархии подклассов.
Возможность применения: Если бы потребовалось различать поведение разных типов сотрудников (например, Manager получает бонусы, а Developer — опционы), можно было бы создать подклассы и переопределить метод calculate_total_income().
В текущем коде полиморфизм проявляется в использовании стандартного интерфейса print() и методов списка list, которые одинаково работают с любыми объектами WORKER.
7. Соответствие требованиям
Реализация полностью удовлетворяет условиям Кейс-задачи № 3:
Класс назван WORKER.
Содержит требуемые поля (ФИО, должность, ЗП, год приема).
Реализован ввод данных с клавиатуры.
Реализован вывод сотрудников со стажем больше заданного.
Предусмотрено сообщение, если таких сотрудников нет.
Использованы конструкторы, деструктор, методы доступа.
Данные хранятся в динамическом списке (list).
Код разделен на модули (worker.py и main.py).
8. Тестирование
Для проверки корректности работы были проведены следующие тесты (ментальные и ручные):
Тест валидации: Попытка создать сотрудника с отрицательной зарплатой -> Ожидается ValueError. Результат: Успешно.
Тест расчета стажа: Сотрудник принят в 2020 году. Текущий год 2026. Ожидаемый стаж: 6 лет. Результат: Верно.
Тест поиска: Ввод стажа 10 лет. В списке есть сотрудник 2015 года (стаж 11 лет) и 2020 года (стаж 6 лет). Должен вывестись только первый. Результат: Верно.
Тест пустого результата: Ввод стажа 100 лет. Сообщение «Сотрудников не найдено». Результат: Верно.

10. Итерация и рефакторинг
После первоначальной написания кода был проведен анализ с целью улучшения:
Улучшение 1: Изначально год приема мог быть введен неверно (например, 3000 год). Добавлена проверка в сеттер year_hired на диапазон лет.
Улучшение 2: Вместо хранения стажа как поля, который нужно обновлять каждый год, реализован метод get_experience(), что делает данные всегда актуальными.
Улучшение 3: Вынесение класса в отдельный модуль worker.py улучшило читаемость основного скрипта main.py и соответствует принципу разделения ответственности.
